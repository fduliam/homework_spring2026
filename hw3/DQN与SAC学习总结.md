## 1. 从 HW2 到 HW3：目标没变，学习路线变了

强化学习的基本任务仍是：找到一个策略，让与环境交互得到的期望累计奖励尽可能高。

- 状态 s：智能体当前所处的情况。
- 动作 a：当前选择的操作。
- 奖励 r：环境对这一步的评分。
- 策略 π：从状态到动作选择的规则，可能是概率分布。
- 折扣 γ：未来奖励相对于当前奖励的权重。

**一条轨迹的折扣回报 = r₀ + γr₁ + γ²r₂ + ……**

HW2 的策略梯度直接调整策略的动作概率：表现好的动作，提高其概率；表现差的动作，降低其概率。

HW3 增加了另一条路线：先学习状态或动作的长期价值，再利用价值来改进决策。

| 方法 | 主要学习对象 | 怎么选择动作 |
|---|---|---|
| HW2 policy gradient | 策略网络 π | 从策略分布中采样 |
| DQN | 动作价值网络 Q | 选择 Q 最大的离散动作，训练时额外探索 |
| SAC | 策略网络 π 和动作价值网络 Q | actor 生成连续动作，critic 评价并指导 actor |

**不是有了一个更新的算法就换了奖励目标，而是求解同类决策问题的方法发生了变化。SAC 还加入了熵正则化，因此训练目标并不只是原始环境奖励。**

## 2. Q、V 和 advantage 分别是什么？

### 2.1 Q 必须说明后续按照什么策略行动

**Qπ(s,a) = 在状态 s 执行动作 a，随后按照策略 π 行动时的期望折扣回报。**

**Q*(s,a) = 在状态 s 执行动作 a，随后按照最优策略行动时的期望折扣回报。**

Qπ 是对指定策略的评价；Q* 是最优动作价值。不能把所有 Q 都直接定义为“后续最优”的价值。

DQN 朝 Q* 学习。SAC 的 critic 学习带有熵项、与当前策略相关的软动作价值，通过策略评价和策略改进交替优化。

### 2.2 V 与 Q 的区别

- Vπ(s)：在状态 s 按策略 π 选择动作后，平均能获得多少长期回报。
- Qπ(s,a)：先指定一个动作 a，再按 π 继续，能获得多少长期回报。

**Vπ(s) = 按 π 的动作概率，对 Qπ(s,a) 求平均。**

**Aπ(s,a) = Qπ(s,a) − Vπ(s)**，表示这个动作比该状态下的策略平均水平好多少。

HW2 的 baseline 通常近似 Vπ。HW3 的 Q critic 不只是减方差的 baseline，还直接参与动作选择或 actor 优化。

上面的 Vπ 与 Qπ 关系针对普通奖励价值。采用 SAC 的软价值约定时，还要加当前状态的熵：**V_soft(s) = 按策略求平均〔Q_soft(s,a) − α log π(a|s)〕**。不要混用两个定义。

## 3. Bellman 方程：为什么可以只看一步？

### 3.1 从回报拆分开始

**从当前开始的回报 = 当前奖励 + γ × 从下一步开始的回报。**

这只是把累计回报拆成两段，不是近似。对未来的不确定性取条件期望，就得到价值函数的递归关系。

### 3.2 固定策略的 Bellman 期望方程

**Qπ(s,a) = 对环境转移、奖励和下一动作取期望〔r + γQπ(s′,a′)〕**

其中下一动作 a′ 按 π(·|s′) 采样。

随机环境中，不能把某一条经历的 r + γQ(s′,a′) 当成精确的 Q(s,a)。等式在相应的期望下成立。

### 3.3 Bellman 最优方程

**Q*(s,a) = 对环境转移和奖励取期望〔r + γ × max Q*(s′,a′)〕**

这里对下一动作取最大值，因为后续要按最优决策行动。

例如，S1 → S2 → 终止，每次转移奖励 1，γ=0.9：

- 在 S2 执行动作后终止，价值为 1。
- 在 S1 的价值为 1 + 0.9 × 1 = 1.9。

Bellman 方程把长期回报的关系写成了局部递归，但实际学习仍需要足够数据、状态动作覆盖和反复更新，不能理解为“一步就知道所有未来”。

## 4. TD 和 bootstrapping：训练答案不是完全真实的标签

DQN 使用采样经历构造目标：

**y = r + γ × (1−d) × max Q_target(s′,a′)**

**TD 误差 = y − Q_online(s,a)**

**critic loss = batch 中 TD 误差平方的平均值。**

d 表示真正的环境终止。终止后没有后续回报，所以 y=r。

这里 y 有两部分：真实获得的即时奖励，以及目标网络预测的未来价值。**因此 y 是训练参照，不是 ground truth。**用预测来构造另一处预测的训练目标，就是 bootstrapping（自举）。

和蒙特卡洛回报的区别：

| 蒙特卡洛 | TD 自举 |
|---|---|
| 通常等待一段完整轨迹，用实际奖励计算回报 | 用一步奖励加未来价值预测 |
| 受完整轨迹随机性影响 | 受 critic 预测误差影响 |
| 不需要未来价值预测作为回归目标 | 可以较早更新，并复用单步经历 |

### 为什么 target 放在 `no_grad()` 内？

更新在线 Q 时，把本次 y 当作固定参照，只对 Q_online(s,a) 求导，而不通过 target 回传。这通常称为**半梯度更新**。

在线网络的更新和目标构建不需要同时沿所有数学依赖求导。对自举目标也求导，会变成不同的学习方法。

代码位置：`src/agents/dqn_agent.py:71`、`src/agents/sac_agent.py:198`。

## 5. Replay buffer：旧经历反复用，目标每次重新算

缓冲区存的是：

**(s, a, r, s′, d)**

这些是过去实际发生的交互事实，通常不存旧的 Q 值或旧 target。

每次训练从缓冲区随机抽 batch，再根据当前网络重新计算预测与 target。因此同一条经历被重复抽到，target 可能已经不同。

### 为什么能使用旧策略产生的数据？

Q-learning 的目标下一动作由最大化操作确定，不要求数据中的动作来自当前贪心策略。环境动力学和奖励不变时，历史的状态—动作—奖励—下一状态仍然提供有效信息。

这就是 off-policy 的含义：**采集数据的行为策略，可以不同于我们正在评价或改进的策略。**SAC 同样可以用历史 transition 训练当前 actor 和 critic。

两个主要好处：

1. 一次环境交互的经历可以用于多次更新，提高利用率。
2. 随机抽样打散连续轨迹的相关性，通常有利于优化。

但 replay 数据并不会因此变成严格独立同分布的数据，也不保证训练稳定。

**纠正一个容易产生的误解：随机策略采集的数据不是“烂数据”。**它们可以覆盖当前策略很少访问的动作和状态。旧数据是否不合适，应根据覆盖、任务变化和分布分析，不能仅凭“比较旧”判断它一定拖后腿。

### learning_starts / training_starts

这是收集经历的预热阈值，达到后才更新网络。预热可以避免缓冲区很小时反复拟合少量重复数据，并给最初 batch 提供更多样的经历。

预热不是因为随机数据不能学习。Q-learning 本来就允许从随机探索经历中学习。

## 6. Target network：减缓移动的训练目标

如果训练预测和 target 都依赖同一个快速变化的网络，更新一处参数可能同时改变大量训练目标。这会增加优化难度。

目标网络是一份独立参数快照，用来减缓目标变化：

- **硬更新：**每隔 K 个训练环境步，将在线网络参数整体复制到目标网络。
- **软更新：**每次更新后，目标参数 = (1−τ) × 原目标参数 + τ × 在线参数。

例如 τ=0.005，混入在线参数的 0.5%，保留原目标参数的 99.5%。

**target 网络有帮助，但不是所有 Q-learning 方法数学上都必须使用，也不保证神经网络收敛。**硬更新先后顺序是一种实现约定；先训练再同步能使用最新参数，但先同步再训练不等于“毫无意义”。

`target_update_period` 控制同步间隔，**不是 critic 的梯度更新次数**。

SAC 名称里的 Soft 指熵正则化，不是这里的 soft target update。

## 7. DQN 的探索与像素输入

### 7.1 ε-greedy

- 以概率 ε：均匀随机选一个动作。
- 以概率 1−ε：选在线网络 Q 值最大的动作。

ε 是“进入随机分支的概率”，不是“选择非贪心动作的概率”：随机分支也可能恰好选到贪心动作。

在 basic DQN 配置中：

- 初始 ε=1。
- 总训练进度 30% 时降到 0.1。
- 60% 时降到 0.02，此后保持不变。
- 两个锚点间分段线性插值，不是突然跳变。

`get_action` 面向单条观测和环境交互。critic target 中的 argmax 面向整个 batch 的假想后续动作，不需要走 ε-greedy 接口。

### 7.2 Atari 与 MLP 的切换

CartPole 和 LunarLander 用少量状态数字作为输入，可以使用 MLP。

MsPacman 使用四帧堆叠的 84×84 灰度图，CNN 提取图像特征。配置中的 `make_critic` 工厂自动切换网络，DQNAgent 不需要知道具体使用 MLP 还是 CNN。

二者都输出 **(batch_size, num_actions)**，所以 argmax、gather 和 Bellman 更新逻辑可以共用。

本次 Atari 一个训练环境步经过 frame skip=4，不应把横轴计数直接等同于原始游戏帧数。现有包装记录原游戏分数，没有启用文件中另定义的奖励裁剪包装。

## 8. Double DQN 与 clipped double-Q 不要混为一谈

### 8.1 max 为什么可能高估？

若多个价值估计都有误差，取最大值更容易选中“误差恰好偏正”的那个。即使单个估计无偏，最大值的期望也可能偏高。

但不能从任何一次训练回报下跌就认定存在过高估计，需要额外校准证据。

### 8.2 Double DQN：选动作与估值分开

普通 DQN：

- 用目标网络选下一状态最好的动作。
- 用目标网络评价这个动作。

Double DQN：

- **a′ = 在线网络在 s′ 下 Q 最大的动作。**
- **y = r + γ(1−d)Q_target(s′,a′)。**

目标网络不是 Double DQN 独有的。二者都用它构造目标，区别是下一动作由谁选。

在线和目标网络的误差并不独立，因此这是减少高估的机制，不是精确消除偏差的保证。

### 8.3 Clipped double-Q：两个 critic 对同一动作取较小估计

假设 Q₁(s′,a′)=100，Q₂(s′,a′)=70，目标采用 70。

**backup Q = min(Q₁_target(s′,a′), Q₂_target(s′,a′))。**

clipped 指用另一份估计限制偏高的值，不是裁到固定上下限。它可能引入低估。

| 技巧 | 处理对象 |
|---|---|
| Double DQN | 分开动作选择与价值评价 |
| clipped double-Q | 两份 Q 估计取最小值 |
| PPO clipping | 限制新旧策略概率比的代理目标 |
| gradient clipping | 梯度范数过大时缩放梯度 |

本作业实现将 min 用在 target backup，actor 的 Q 项仍对 critic 求平均。常见 SAC 变体会让 actor 也优化 min-Q，不能把这些变体不加区分地当作当前作业同一实现。

## 9. SAC：连续动作怎么优化？

DQN 的离散动作可以枚举比较。一般的连续动作 Q 最大化是非线性优化问题，无法直接枚举；不意味着连续动作领域不存在 Q-learning 方法，而是标准 DQN 的动作选择方式不直接适用。

SAC 学习一个 actor 来生成动作，用 critic 指导它：

**状态 → actor 动作分布 → 连续动作 → critic(s,a)。**

SAC critic 输入状态和给定动作，输出一个值。多个 critic 堆叠后的形状为 **(num_critics, batch_size)**。

### 9.1 Critic target

先从当前 actor 在下一状态下的分布采样 a′。

**y = r + γ(1−d) ×〔目标 Q 的 backup + α × 下一状态熵估计〕。**

- 回归左边 Q(s,a) 的 a 是 buffer 中实际执行过的动作。
- 右边下一动作 a′ 是当前 actor 新采样的动作。
- 熵估计可以使用 −log π(a′|s′)。本实现通过 entropy 函数另采动作，统计期望相同但采样噪声结构不同。
- 本次更新只对在线 critic 的左边预测求导。

### 9.2 Actor loss

**actor loss = −平均 Q(s,actor 采样动作) − α × 平均熵。**

最小化负 Q 相当于提高 Q；减去熵相当于鼓励保留随机性。

actor 更新不使用 buffer 里的旧动作作为要模仿的标签，而在 buffer 状态上生成新动作。critic 参数在这次 actor 步骤中不由 actor 优化器更新，但 Q 对动作的梯度必须保留。

## 10. sample、rsample 与 HW2 梯度的联系

### 10.1 sample

从分布采样，但采样出的动作不保留到分布参数的路径梯度。

只计算 Q(s, sample 动作) 再 backward，不能沿这个动作把梯度传回 actor。

环境交互只需要动作；critic target 在 no_grad 下计算，所以这些地方用 sample 即可。

### 10.2 rsample

正态分布采样可以改写为：

**ε 从标准正态分布采样；a = μ + σ × ε。**

随机噪声不依赖 actor 参数，而 μ 和 σ 由 actor 产生，因此动作对 actor 参数可微。

**梯度路径：Q → 动作 → μ、σ → actor 参数。**

动作经过 tanh 后仍可微。分布中的 log_prob 必须包括变换的 Jacobian；作业的 TransformedDistribution 已经负责这一点。

### 10.3 HW2 为什么用 sample 仍能训练策略？

HW2 使用似然比梯度：将采到的动作视为固定数据，通过 log πθ(a|s) 求导，不穿过动作采样。

- HW2：“这个动作好，就提高它出现的概率。”
- SAC：“critic 给出动作变化对价值的影响，通过动作把方向传回 actor。”

路径梯度通常具有较好的方差性质，但依赖可微且有用的 critic；SAC 不需要对真实环境求导。

## 11. 熵和温度：不是越随机越好

### 11.1 为什么鼓励熵？

critic 不准确时，actor 如果太早只生成一种动作，可能不断收集相似经历，失去发现更好动作的机会。

熵奖励鼓励保留多种选择，减少过早集中。但高熵不保证有用探索，也可能影响精确控制。

**熵描述相同状态下动作分布的分散程度，不是机器人运动幅度或速度。**

连续动作使用微分熵，数值可以为负，也依赖动作坐标尺度。负熵不是“负随机性”。

作业的 Independent 分布已将动作维作为一个 event，log_prob 输出 **(batch_size,)**，不能再盲目对 dim=1 求和。entropy 函数返回每个状态的 −log_prob，调用方需要时再对 batch 求均值。

### 11.2 温度 α

α 是熵项的权重，不是动作标准差，也不是目标网络软更新率 τ。

- α 小：更侧重 Q 值，较愿意牺牲随机性。
- α 大：更重视熵，较愿意为随机性付出价值代价。

固定 α 不会固定熵。策略仍可以随任务学习变得集中。它与 LLM 解码时直接缩放 logits 的采样 temperature 不是同一操作。

### 11.3 环境奖励和熵正则化分开

本次 HalfCheetah 的环境奖励：

**r = 向前速度 − 0.1 × 六个控制动作的平方和。**

SAC 训练加入熵正则，但图上的 Eval_AverageReturn 仍是每局原始环境奖励的不折扣总和，再对评估回合平均，没有把熵加到展示分数中。

Q 包含折扣与未来熵项，而且日志是在 replay batch 上平均，所以不能与不折扣评估回报直接比较大小来判断准确性。

## 12. 自动温度：从约束要求到梯度反馈

### 12.1 先复习梯度下降

损失衡量某个目标。导数表示当前参数增加一点，损失将如何变化。

**新参数 = 旧参数 − 学习率 × 梯度。**

梯度为正就倾向于减小参数，梯度为负就倾向于增大参数。下降指损失下降，不是参数必须减小。

例如 loss=(w−3)²，w=1 时导数为 −4，学习率 0.1：新 w=1.4，损失从 4 降到 2.56。

代码中的 zero_grad 清梯度，backward 计算梯度，optimizer.step 调参数。Adam 使用梯度历史调整更新，不等于裸的固定学习率梯度下降。

### 12.2 最低平均熵约束

用一个简化的平均形式理解：

**最大化期望奖励，同时要求平均熵 ≥ 目标熵。**

引入非负权重 α，构造拉格朗日函数：

**L = 期望奖励 + α ×（平均熵 − 目标熵）。**

更严谨的 SAC 推导会明确状态分布、折扣或逐时间步约束；这里用于理解当前标量温度的反馈方向。

- 固定 α，actor 提高 L，兼顾奖励和熵。
- 更新 α 时，将当前策略视为固定，沿降低 L 的方向调整权重。

L 对 α 的导数是 **平均熵 − 目标熵**。因此对 α 的直接梯度下降为：

**新 α = 旧 α + 学习率 ×（目标熵 − 当前平均熵），再限制 α 非负。**

这正是熵不足提高温度、熵有余降低温度的反馈。写条件语句也可以实现这类规则，拉格朗日方法给出它与约束优化的联系。

### 12.3 为什么温度要最小化，而 actor 要最大化？

这是原始—对偶更新，不是所有参数共同下降同一个损失。违反约束时，熵余量为负，增大 α 会降低这个不合格策略的 L，从而使下一次 actor 优化更重视约束。

从对偶观点，对每个 α，考虑策略能获得的最大 L；这个值给约束问题的最优奖励一个上界，再选择 α 尽量收紧上界。神经网络和近似交替更新不保证精确求得全局解。

**不是维持 L 恒定，也没有给 L 设一个预期值。**真实奖励提高时，L 可以提高。每次固定 actor 更新 α 只是局部步骤，随后 actor 也会响应新的权重。

### 12.4 本代码实际学习 log_alpha

学习 u=log_alpha，并通过 **α=exp(u)** 保证正数。

两种需要区分的损失：

- 直接对偶形式：平均〔exp(u) ×（−log_prob − 目标熵）〕。
- 本实现的常见替代形式：平均〔u ×（−log_prob − 目标熵）〕。

两者方向相同，但对 u 的梯度相差 α 缩放，不是完全等价的优化过程。

本实现见 `src/agents/sac_agent.py:325`。log_prob 在 actor 返回时 detach，所以温度更新不会反向更新 actor；get_temperature 返回普通数值给 actor/critic 作权重，训练温度时必须直接使用有梯度的 log_alpha。

目标熵采用 **−动作维度**：倒立摆 −1，HalfCheetah −6。它是经验设定，不是每个任务的理论最优随机程度，也不要求每个状态或每次日志恰好等于目标。

**自动温度减少手动选权重的负担，但仍有目标熵、温度学习率等选择，不保证优于已经合适的固定温度。**

## 13. 训练步、batch、更新和评估不要混淆

本次训练循环在预热结束后通常是：

**每交互一步存一条新经历 → 抽一个历史 batch → 更新网络。**

- DQN 每次 update 做一次 critic 优化器更新。
- 本次 SAC 配置每次 update 做一次 critic 更新、一次 actor 更新；自动温度开启时再做一次温度更新。
- 双 critic 使用同一个 critic 优化器，在一次反向传播中一起训练；不是对每条样本逐个训练两次。
- num_critic_updates 控制每次调用 update 内训练 critic 的次数；batch_size 控制一次损失包含多少 transition。

评估按照训练环境步数周期触发，在独立环境中额外运行 10 个回合：

| 实验 | 预热结束 step | batch size | 评估间隔 |
|---|---:|---:|---:|
| CartPole DQN | 1000 | 128 | 2500（命令覆盖默认值） |
| LunarLander Double DQN | 20000 | 64 | 10000 |
| MsPacman Double DQN | 20000 | 32 | 10000 |
| 倒立摆 SAC，固定/自动温度 | 5000 | 128 | 5000 |
| HalfCheetah SAC，固定/自动温度 | 10000 | 256 | 5000 |
| Hopper SAC，各种设置 | 10000 | 256 | 5000 |

评估不更新网络、不入训练 replay，也不计入横轴的训练环境步数。DQN 评估默认贪心；当前 SAC 评估仍从 actor 分布采样，并非直接使用均值动作。

step 从 0 开始，评估判断与预热无关，所以 step=0 也有初始评估。50 万步的循环最后索引 499999，若间隔 5000，最后评估为 495000。训练结束只额外保存，没有默认再评估最终模型。

真正终止与时间限制截断也不同：当前实现重置环境时看 done，决定是否取消 bootstrap 时使用 **done 且不是 TimeLimit.truncated**。

自动调节确实工作，但本次固定温度达到目标更早。不能说自动温度必然学得更快。

### 14.4 Hopper：公式正确还不够，网络设计也重要

| 指标 | 单 critic，tanh | 双 critic，tanh | 双 critic，ReLU |
|---|---:|---:|---:|
| 最高平均回报 | 1060.42 | 939.33 | 3370.35 |
| 最后一次平均回报 | 1027.89 | 845.76 | 2935.04 |
| 最后 10 次评估均值 | 817.21 | 878.55 | 2945.73 |
| 最后 10 次平均回合长度 | 242 | 247 | 850 |
| 达到平均 1500 的评估次数 | 0 | 0 | 65 |

原 tanh 双 critic 曲线更平稳，但未达到平均 1500。模型诊断确认两组通常在约 250～280 步因高度或角度不健康终止；改用均值动作也没有解决短回合问题。

检查终止 mask、min backup、重参数化、熵项和软更新没有发现主路径错误。对实际访问状态测得 critic 最后隐藏层约 92% 的 tanh 输出绝对值大于 0.99，提示饱和可能限制学习。

为此新增 `experiments/sac/hopper_clipq_relu.yaml`：仅改变 actor/critic 的隐藏激活与实验名称，保留动作输出 tanh、所有训练预算和其他主参数。

ReLU 对照首次平均达到 1500 在 85000 步。对最终保存模型的额外 10 局诊断，平均约 3007，7 局坚持到 1000 步，但仍有一局很早摔倒。

**结论：这个网络设计改动在本次运行中有效，改善了持续存活，而不只是把 Q 预测抬高。**但不能证明 tanh 饱和是唯一原因，也不能证明 ReLU 普遍最佳：actor 和 critic 同时改了，且每种设置仅训练一次。

单 critic tanh 与双 critic ReLU 同时改变两个因素，不能用它们直接证明“双 critic 更好”。原单/双 tanh 是 critic 对照，双 tanh/ReLU 才是激活对照。

### 14.5 函数逼近器不是激活函数

函数逼近器是用于近似 π、Q 或 V 的整个模型。模型类型、深度、宽度、激活以及学习到的权重共同决定其行为。激活只是其中一部分。

tanh 隐藏层饱和可能削弱局部梯度，但神经网络仍可能存在非零梯度。ReLU 也可能出现长期不激活的单元，换激活不是万能修复。

## 15. DQN 超参数：各自在影响什么？

**本节是理论整理与候选对照方案，没有执行 DQN 超参数扫描。**

当前 LunarLander 基准：Double DQN，50 万步，学习率 0.001，2 层各 256，batch 64，预热 20000，同步间隔 1000，γ=0.99。

| 参数 | 控制内容 | 可能的权衡 |
|---|---|---|
| learning_rate | 每次优化的步幅尺度 | 小可能进展慢，大可能振荡或发散；实际参数变化还取决于梯度和 Adam |
| target_update_period | 目标网络同步间隔 | 小更及时但靶子变化快，大更稳定但滞后 |
| hidden_size | 隐藏层宽度 | 大提高表达容量，但不保证更好拟合或更稳定 |
| num_layers | 隐藏层深度 | 影响表达与优化难度，不是越深越好 |
| batch_size | 一次更新采样的 transition 数 | 大通常降低部分采样噪声，但改变计算量和优化行为 |
| learning_starts | 预热采样阈值 | 早能更早学习，晚能先获得更多数据；比较时更新总次数也会变 |
| clip_grad_norm | 梯度范数上限 | 限制异常大更新，太严格可能压制有效梯度 |
| discount | 对未来奖励的权重 | 大更长远也增加自举传播难度；它改变目标，不只是优化速度 |
| ε schedule | 探索分支概率及衰减速度 | 过早降低可能覆盖不足，过高也可能持续扰动有效行为 |

**不能把这些参数混同：**batch_size 是每次用多少数据，learning_rate 是步幅，target_update_period 是复制间隔，num_critic_updates 是更新次数。

### 15.1 可以选择的四组方案

只选一个变量，其他设置保持一致：

- 学习率：0.0001、0.0003、0.001（已有基准）、0.003。
- 目标网络间隔：250、500、1000（已有基准）、2000。
- 网络宽度：64、128、256（已有基准）、512。

这些值只是探索候选，不是经过验证的最佳配置。按 PDF 第 2.6 节，本来需要基准加至少三种设置并画同轴学习曲线；这项实验明确跳过。

### 15.2 哪些参数不能随便加到 YAML 就以为生效？

现有 basic_dqn_config 支持学习率、深度、宽度、batch、预热、折扣、梯度裁剪和目标间隔等字段。探索 schedule 在 `src/configs/dqn_config.py:51` 硬编码，需要先暴露配置接口才能做系统对照。

本次新增 hidden_activation 只用于 SAC，**没有把 DQN 隐藏激活也改成可配置**。未知 YAML 字段可能被 `**kwargs` 接住并出现在配置里，但不一定真正改变网络，所以必须核查调用链。

run_dqn 的命令行也不是任意参数都能覆盖；不要凭空添加 --learning_rate 或 --total_steps，应该使用对应 YAML 或先实现明确的接口。

### 15.3 怎么判断一个参数更好？

至少比较：

1. **学习速度：**达到指定回报用了多少训练环境步。
2. **末期表现：**最后若干次评估的平均回报，而不只看峰值。
3. **波动与退化：**已学会的能力是否反复丢失。
4. **计算与样本预算：**同样环境步数不等于同样梯度计算量。
5. **可重复性：**多随机种子是否有一致趋势。

改变 γ 会改目标；改变预热会改变更新次数；改变总步数还会影响按进度定义的 ε 曲线。这些都要明确，不宜把任何“更高分”直接归因于单一想象中的机制。

## 16. 实现中的易错点

- 字典 `**batch` 按名字匹配，参数名必须一致；按位置传参则要求顺序一致。
- buffer key 是 observations/actions/rewards/next_observations/dones。DQN 方法的参数名与它不同，SAC 方法则相同。
- from_numpy 保留 int64 和 bool，只将 float64 转 float32；不能声称所有 action 都被转浮点数。
- gather 索引要 long，取每行指定动作用 unsqueeze 后 gather，再 squeeze 指定的维度。
- `1−done` 对 bool tensor 不合法，本实现使用 `1−done.float()`。
- SAC log_prob 已对动作维度求和，不要再次 sum(dim=1)。
- q_values.mean(dim=0) 只消除 critic 维，仍是 batch 向量；需要标量损失才能无参 backward 和 item。
- actor 更新不能 detach 采样动作或 Q，也不能把 Q 前向放进 no_grad。
- critic target 和温度用到的 actor log_prob 则应避免错误的梯度回传。
- 最后一条 loss 与最后一次 eval 不是同一采样对象；日志近似或曲线相关不等于因果证据。

## 18. 收尾与后续学习

这次最大的收获可以连成一条链：

**长期回报的定义 → Bellman 递归 → 采样自举回归 → replay 与目标网络 → 利用 Q 改进动作 → 用熵保留探索 → 用约束反馈调温度。**

我需要记住的不是某一组最优参数，而是：

1. 训练参照可以来自预测，预测误差也会被传播。
2. 模型可以复用旧经历，但这与“监督学习数据永远固定且完全可靠”不同。
3. 学会一次、不再退步、多种子稳定成功，是三个不同层次。
4. 较低 loss、较小 Q 值或一次达标，都不能单独证明实现和解释正确。
5. 梯度能否传播、模型能否表达、数据是否覆盖、目标如何定义，需要分别检查。
6. 自动温度是学习约束权重，不是保持 L 恒定，也不保证最高环境回报。
7. 实验失败有价值：Hopper 的失败帮助区分了公式错误、短回合行为和模型饱和，并促成可检验的对照。

后续 HW4 的 LLM RL 又会回到策略梯度框架：动作成为 token，回答成为轨迹，最终评分成为 reward。HW2 的 log-prob × advantage、这里对采样/梯度/熵/参考目标的理解，会帮助理解组内优势、KL 正则和 PPO 式样本复用。但不要把 SAC 路径梯度直接当作对离散 token 可用的同一种方法。
