# HW2 学习笔记：策略梯度的理论基础

这份笔记是自己学习用的，记录做 HW2（Policy Gradients）过程中理清楚的理论要点，重点是数学推导和它与后续方法（PPO、DPO）的关系，不涉及代码实现细节。

## 1. 强化学习的优化目标，以及为什么它不能直接求梯度

强化学习要优化的目标函数是期望轨迹回报：

J(θ) = E_{τ~π_θ(τ)} [ r(τ) ]

写成积分形式：

J(θ) = ∫ π_θ(τ) · r(τ) dτ

这里 τ 是一条完整轨迹（状态、动作序列），π_θ(τ) 是在参数 θ 下这条轨迹发生的概率，r(τ) 是这条轨迹的总奖励。

**问题在于，这个期望本身是关于 θ 的函数，因为采样轨迹所用的分布 π_θ(τ) 本身依赖 θ。** 这和一般的监督学习不同：在监督学习里，训练数据的分布是固定的，不随参数变化；而在强化学习里，用来估计目标函数的数据（轨迹）本身是由当前策略采出来的，策略一变，数据分布就变。

如果直接对 θ 求导：

∇J(θ) = ∫ ∇π_θ(τ) · r(τ) dτ

这里出现的是 **∇π_θ(τ)**，也就是概率本身的导数，不再是"概率乘以某个函数再积分"的标准期望形式。期望的定义要求积分里必须是一个概率分布本身（不是它的导数）乘以某个函数，这样才能写成 E[...] 的形式，并通过采样去估计。现在这个式子无法直接采样估计，因为没法从"概率的导数"里采样。

这就是 policy gradient theorem 要解决的核心问题：**把这个无法采样估计的导数，转化成一个可以采样估计的期望。**

## 2. 似然比技巧：把导数变回"概率乘以某个量"

对数函数求导的链式法则给出一个恒等式：

∇log π_θ(τ) = ∇π_θ(τ) / π_θ(τ)

两边同乘 π_θ(τ)：

**∇π_θ(τ) = π_θ(τ) · ∇log π_θ(τ)**

这就是似然比技巧（log-derivative trick）。它本身只是一步纯代数变形，不涉及任何强化学习特有的性质，可以用具体数字验证：假设某个分布里 π_θ = 0.3，∇π_θ = 0.06，那么 ∇log π_θ = ∇π_θ / π_θ = 0.06 / 0.3 = 0.2；反过来验证，π_θ × ∇log π_θ = 0.3 × 0.2 = 0.06，正好等于 ∇π_θ。

把这个恒等式代回原来卡住的积分：

∇J(θ) = ∫ ∇π_θ(τ) · r(τ) dτ = ∫ π_θ(τ) · ∇log π_θ(τ) · r(τ) dτ

**现在 π_θ(τ) 又出现在"乘以某个函数再积分"的位置上了**，这正好符合期望的定义，可以写成：

∇J(θ) = E_{τ~π_θ} [ ∇log π_θ(τ) · r(τ) ]

**这一步就是从"无法采样估计的导数"变成"可以采样估计的期望"的关键转换。** 只需要按当前策略采集若干轨迹，分别算出每条轨迹的 ∇log π_θ(τ) 和 r(τ)，相乘再平均，就是梯度的一个无偏估计。

## 3. 展开 log π_θ(τ)：为什么策略梯度不需要知道环境动力学

一条轨迹的概率，按时间顺序拆开是初始状态分布、每一步的策略选择概率、每一步的环境转移概率三者相乘：

π_θ(τ) = p(初始状态) × ∏_t π_θ(动作_t | 状态_t) × ∏_t p(状态_{t+1} | 状态_t, 动作_t)

取对数后，乘法变成加法：

log π_θ(τ) = log p(初始状态) + Σ_t log π_θ(动作_t | 状态_t) + Σ_t log p(状态_{t+1} | 状态_t, 动作_t)

对 θ 求导时，**初始状态分布和环境转移概率都不依赖 θ（环境动力学是固定的，不是可调参数），梯度为 0，直接消失**。只剩下：

∇log π_θ(τ) = Σ_t ∇log π_θ(动作_t | 状态_t)

这一点很重要：**它说明完全不需要知道环境内部是怎么转移的，只需要知道策略网络在每一步输出的动作概率分布，就能算出整条轨迹的梯度方向。** 这正是策略梯度属于 model-free 方法的原因。

把两步拼起来，得到最终落地的公式：

∇J(θ) = E [ ( Σ_t ∇log π_θ(动作_t | 状态_t) ) · r(τ) ]

这正是 `MLPPolicyPG.update` 里那一行代码对应的数学形式：用 `.log_prob(actions)` 算出每个时间步的对数概率，乘以某个标量（最初是整条轨迹的奖励 r(τ)），再取平均，最后取负号做梯度下降（因为优化器是最小化损失，而这里要最大化目标）。

## 4. 方差削减手段：都没有改变目标本身，只是替换了乘在 log π 后面的标量

HW2 里 reward-to-go、baseline、GAE 做的所有事情，本质上都是在**不改变上面这个期望的前提下**，把乘在 ∇log π_θ 后面的那个标量，替换成一个方差更小、但期望值相同（或近似相同）的量。

### 4.1 reward-to-go：因果性带来的无偏方差削减

原始公式里每个时间步都乘以整条轨迹的总奖励 r(τ)，这意味着评价第 t 步动作时，也把 t 之前已经发生的奖励算进去了。但**当前动作不可能影响过去已经发生的奖励**，这是一个因果事实。利用这一点，可以把过去的奖励项从梯度估计里去掉，只保留从当前时刻往后的奖励（reward-to-go）。

这个替换不改变梯度的期望值（可以证明去掉的那部分期望为 0），但通常能降低方差，因为不再让"遥远的过去"的随机性影响"现在"的梯度估计。**这说明这类方差削减手段不是随意的工程技巧，背后有明确的数学依据。**

### 4.2 baseline：减去任何不依赖动作的函数，期望不变

可以证明，给公式减去任何一个不依赖动作本身的函数 b(s_t)（即 baseline），期望依然不变：

E[ ∇log π_θ(a_t|s_t) · b(s_t) ] = 0

这是因为对动作的期望里，∇log π_θ 本身积分起来就是 0（这是概率分布归一化的必然结果），乘以一个不依赖动作的常数 b(s_t) 之后仍然是 0。所以减去 baseline **只影响方差，不引入偏差**。

**critic 存在的全部意义，就是提供一个尽量准确的低方差 baseline**，并不是在直接告诉策略"应该怎么做"。critic 学的是状态价值 V(s)，用它作为 baseline，相当于把"这个动作比这个状态下通常能拿到的回报好多少"作为训练信号，而不是"这个动作本身拿到了多少回报"。这是 actor-critic 架构的理论基础。

### 4.3 GAE：用 lambda 在"相信 critic"和"相信实际采样"之间连续取值

GAE 的递推公式：

当前时刻的优势 = 当前时刻的 TD 误差 + gamma × lambda × 下一时刻的优势

其中 TD 误差 δ_t = r_t + gamma × V(s_{t+1}) − V(s_t)。

- **lambda = 0**：优势就等于当前这一步的 TD 误差本身，完全依赖 critic 对下一状态的预测。方差最小，但如果 critic 预测不准，偏差会被直接放大。
- **lambda = 1**：累加所有未来的 TD 误差，等价于"实际 reward-to-go 减去 critic 预测"，更贴近真实采样结果，偏差小，但方差大。
- **中间值**：在两者之间做偏差-方差权衡。

**HW2 的 LunarLander 实验里，lambda=0 表现最差（五组里唯一没达标的）。** 这不能简单总结为"lambda=0 理论上有缺陷"，更准确的说法是：lambda=0 对 critic 的准确性要求最高，一旦 critic 在某个环境里（比如这种带噪声动作的随机环境）难以学准，lambda=0 就会把这个不准的预测当作事实，持续影响训练。这是"对前提条件更敏感"，不是"普遍意义上更差"。

### 4.4 优势归一化：理论和实践之间的灰色地带

把一批优势减去均值再除以标准差，严格来说会引入一种**依赖当前批次统计量**的偏差（极端情况下，batch size=1 时归一化后的优势恒为 0），但实践中通常能改善训练效果。**这类技巧需要靠实验验证，不能只靠公式推导判断好坏**，这也是 HW2 要求做消融实验、而不是直接相信理论推导的原因。

## 5. 和后续方法（PPO、DPO）的关系

### 5.1 PPO：同一套采样和 advantage 计算，换了一个损失函数

PPO 采集数据的方式、计算 advantage 的方式（包括使用 GAE）、用 critic 做 baseline，这几部分和 HW2 里 `pg_agent.py` 实现的内容基本一致。

PPO 真正不同的地方，只在于 actor 的损失函数：不再是"对数概率乘以优势"，而是换成一个裁剪过的概率比值（clipped surrogate objective）。这个改动是为了解决 vanilla policy gradient 的一个实际限制——**每次参数更新之后，用来估计梯度的那批数据立刻"过期"了**（因为梯度估计依赖 E_{τ~π_θ}，而 θ 一变，这个期望的采样分布就变了），必须重新调用环境采样函数，拿到新策略下的新数据才能继续更新。这一点在 HW2 的训练循环里能直接感受到：`run_training_loop` 每一轮都要先 `sample_trajectories`，再 `agent.update`，不能对旧数据反复更新多次。

PPO 允许对同一批采样数据安全地做多次梯度更新，裁剪机制防止新策略和采集数据时的旧策略偏离太远，避免用"过期"的重要性采样比值去做不可靠的外推。

**结论：把 HW2 的推导和实现理清楚之后，再看 PPO 代码，采样、advantage 计算、critic 更新这些部分应该相当熟悉，差异主要集中在 actor 的损失函数这一处。**

### 5.2 DPO：同一个目标函数，完全不同的求解路径

DPO 处理的仍然是最大化期望奖励这个目标，通常还会加一个相对参考策略的 KL 约束（防止新策略离原始模型太远）。RLHF 在 DPO 之前的标准做法，是用 PPO 去迭代求解这个带 KL 约束的目标——这就回到了上一节的联系，需要先训练一个 reward model，再用 PPO 采样、算 advantage、更新策略。

DPO 的不同之处在于：它先把这个带约束的优化问题求出闭式最优解（最优策略和 reward model 之间存在一个解析关系），再把这个闭式解代入 Bradley-Terry 偏好模型，推导出一个可以直接对策略做监督式优化的损失函数。**整个过程不再需要采样轨迹，不再需要训练独立的 reward model 或 critic，训练方式更接近普通的监督学习。**

能看懂这个推导的前提，是已经清楚：
- 什么是期望奖励目标（HW2 的 J(θ)）
- 什么是 KL 正则化
- 为什么策略梯度需要依靠采样去估计一个本来无法直接求导的期望（似然比技巧）

这些正是 HW2 反复训练的直觉。

### 5.3 整体脉络

| 方法 | 和 HW2 policy gradient 的关系 |
|---|---|
| Policy Gradient（HW2） | 定义了强化学习真正在优化什么（期望轨迹回报），以及为什么必须依靠采样和方差削减手段求解（似然比技巧、reward-to-go、baseline、GAE） |
| PPO | 同一套采样、advantage 计算、critic 结构，换了一个更稳健、允许多次复用数据的损失函数（裁剪概率比值） |
| DPO | 出发点仍是同一个目标函数（期望奖励 + KL 约束），但绕开了采样和迭代更新，通过闭式解把问题转化成监督学习 |

**policy gradient 是整条链路里最基础的一层**：它建立了"目标函数→似然比技巧→可采样估计的梯度→方差削减"这一整套思维方式。PPO 是在同一套结构上换了损失函数；DPO 是换了一条完全不同的求解路径，但出发点没有变。把 HW2 的理论部分理清楚，再看 PPO 和 DPO 的推导，公式之间的对应关系会更容易建立起来。
