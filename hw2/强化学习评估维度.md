# 强化学习的常见评估维度

## 1. 评估的基本问题

强化学习方法的评价不能只看最高回报。通常需要回答四个基本问题。

1. 学到的策略表现如何？
2. 达到目标表现需要多少环境样本？
3. 训练和部署需要多少计算资源？
4. 结果是否稳定、可靠，并能适应条件变化？

根据应用场景，还需要评价泛化能力、安全性和约束满足情况。不同任务不一定需要覆盖所有维度，但必须明确实验要验证的主张。

## 2. 主要评估维度

| 维度 | 核心问题 | 常见指标或实验 |
|---|---|---|
| 任务表现 | 策略是否完成任务，完成得多好 | 平均评估回报、成功率、任务特有指标 |
| 样本效率 | 需要多少交互数据才能学好 | 达到目标回报所需环境步数、固定采样预算下的回报 |
| 计算效率 | 需要多少计算资源 | 实际运行时间、CPU/GPU 开销、内存、决策延迟 |
| 稳定性与可靠性 | 能否持续并重复地学好 | 训练后期波动、多随机种子结果、训练失败率 |
| 鲁棒性 | 条件受到扰动后是否仍有效 | 观测噪声、动作误差、环境参数变化、超参数敏感性 |
| 泛化能力 | 在未用于训练的情形中是否有效 | 新地图、新任务实例、新初始条件上的表现 |
| 安全性与约束 | 是否以可接受的方式完成任务 | 碰撞率、违规次数、能耗、最差情形表现 |

### 2.1 任务表现

任务表现衡量学到的策略是否实现了目标。常见指标包括平均评估回报、任务成功率，以及任务本身的业务或物理指标。

例如，CartPole 的目标是维持杆子平衡，HalfCheetah 的奖励则综合考虑运动表现与控制成本。不同环境的奖励定义和数值尺度可能不同，不能直接比较它们的原始回报大小。

评价时应区分以下统计量。

- 最高回报反映某次评估达到的最好表现，容易受到偶然因素影响。
- 最后一轮回报反映训练结束时保存的策略表现，但单次评估可能存在噪声。
- 最后若干轮的平均回报有助于观察训练末期表现，但涉及多个不同的策略检查点，不等于对最终模型重复评估。
- 对最终模型进行多局独立评估，可以估计该模型本身的平均表现及波动。

如果选择最佳检查点，应提前明确选择规则。严格的研究评价还应区分用于选择模型的验证数据与最终测试数据，避免在测试结果上反复挑选模型。

### 2.2 样本效率

样本效率衡量达到目标表现需要多少环境交互数据。环境一步通常对应一次动作执行及其反馈，而不是一整局。

常见评价方式包括以下几种。

- 达到预先设定的目标回报所需的训练环境步数。
- 在相同训练环境步数下，各方法达到的评估回报。
- 在相同采样预算区间内，比较完整学习曲线。

典型图的横轴是训练环境步数，纵轴是平均评估回报。

“首次达到目标”不等于“稳定达到目标”。一次偶然的高分可能使首次达标步数看起来很小。可以补充持续达标情况，或预先规定滑动窗口指标，但不应在观察结果之后随意改变达标标准。

离线强化学习通常还需要说明训练数据集的大小、来源和质量。线上微调场景则应区分已有离线数据与新增环境交互。

### 2.3 计算效率

样本效率高，不意味着计算效率也高。同一批数据可以被用于一次或多次网络更新。更多更新可能提高数据利用率，也可能增加计算开销。

常见指标包括以下内容。

- 达到目标表现所需的实际运行时间。
- 训练使用的硬件类型、数量及计算资源用量。
- 显存或内存峰值。
- 部署时单次决策的延迟与吞吐量。

比较计算效率时，需要说明硬件、并行度、数值精度和实现方式。不能仅凭训练轮数判断哪个方法计算成本更低。调参和失败尝试的总成本也可能影响方法的实际使用价值。

### 2.4 稳定性与可靠性

稳定性至少包含两个层面。

**同一次训练内的稳定性**关注策略是否容易出现明显回退、性能崩溃或持续波动。

**不同训练之间的可靠性**关注更换随机种子后能否重复取得较好结果，以及训练失败的频率。

研究中通常需要运行多个独立训练种子，报告平均表现及标准差、置信区间或其他合适的统计量。图中的阴影区域应明确表示什么，不能混淆标准差、标准误差和置信区间。

重复评估同一个模型不能代替使用多个随机种子重新训练。前者反映固定策略在环境中的评估波动，后者还包含网络初始化、训练采样和优化过程引起的差异。

### 2.5 鲁棒性

鲁棒性衡量条件受到扰动时，方法是否仍然有效。常见测试包括观测噪声、动作执行误差、环境动力学参数变化，以及传感器信息缺失。

超参数敏感性也是一个重要角度。如果算法只在很窄的学习率或 batch size 范围内有效，实际应用时可能需要较高的调参成本。

评价应说明扰动的类型与强度。某种扰动下表现良好，并不能证明对所有扰动都鲁棒。

### 2.6 泛化能力

泛化能力衡量策略是否能处理训练中未使用的情况。例如，在部分地图上训练后，是否能完成新地图中的任务；在部分初始条件下训练后，是否能适应新的初始条件。

评价时需要明确训练与测试的划分，并区分同分布的新样本和明显不同于训练分布的情形。不同测试集用于检查的能力可能不同。

泛化与鲁棒性有一定重叠。前者通常强调未见过的任务或条件，后者通常强调面对扰动时能否保持性能。

### 2.7 安全性与约束

实际系统不仅要求回报高，还可能要求满足安全、资源或业务约束。例如，机器人不能通过频繁碰撞来换取更高任务回报，控制系统也可能受到能耗限制。

常见指标包括碰撞率、约束违反次数、失败概率、累计成本和最差情形表现。训练期间的违规与部署期间的违规可以分别统计。

还需要检查奖励是否真实反映任务目标。策略可能利用奖励设计中的漏洞获得高分，而没有完成预期任务。因此，总回报不能完全替代独立的任务成功指标和安全指标。

## 3. 算法比较与消融实验

算法比较是在不同方法之间进行比较，例如 PPO、DQN 或 SAC。比较时必须考虑各方法适用的任务类型，并保证评价协议和资源预算合理。

消融实验是在同一方法内部移除、更换或调整某个组件，以检查它的作用。HW2 中的主要实验属于这一类。

- 比较 trajectory return 与 reward-to-go，检查收益估计方式的作用。
- 开关 advantage normalization，检查优势标准化的作用。
- 改变 batch size，检查采样量与更新频率的权衡。
- 开关神经网络 baseline，检查价值预测作为参考值的作用。
- 将 critic 更新次数从 5 次降为 1 次，检查基线训练强度的影响。

比较一个组件时，应尽量保持其他条件不变。如果同时改变多个因素，就难以把差异归因于其中某一个因素。

## 4. 公平比较需要对齐什么

### 4.1 先明确比较目标

不存在适用于所有问题的单一公平预算。

- 研究样本效率，应对齐环境交互预算。
- 研究计算效率，应报告相同硬件条件下的运行成本，或明确硬件差异。
- 研究固定更新次数下的表现，可以固定训练轮数，但必须同时报告不同方法消耗的样本量。

仅仅把横轴都写成环境步数，不意味着曲线终点处的预算相同。比较样本效率时，应在相同横坐标处比较，而不是直接比较不同预算下的终点。

### 4.2 保持评价协议一致

需要记录环境版本、奖励定义、单局长度限制、评估局数或步数，以及评估时采用随机动作还是确定性动作。

如果原始指标只统计训练环境步数，应明确是否排除了评估交互。评估虽然通常不用于更新策略，但在真实系统中也可能产生实际成本。

### 4.3 合理控制调参预算

如果一个方法尝试了大量超参数组合，而另一个只使用一组默认配置，结果可能反映的是调参投入差异，而非方法本身的差异。

应说明搜索空间、搜索次数、随机种子数量和模型选择规则。失败的训练和未达标的尝试不应被隐藏。

### 4.4 保留复现信息

建议保存以下内容。

- 代码版本与依赖版本。
- 完整运行命令和最终参数配置。
- Python、NumPy、PyTorch 及环境随机种子的设置方式。
- 硬件、线程数和并行设置。
- 原始日志、模型检查点以及绘图和汇总规则。

仅设置一个名为 seed 的参数，不保证所有随机源都被固定。还需要检查实现是否实际设置了环境及相关库的随机种子。

## 5. 结合本次 HW2 实验理解

### 5.1 CartPole 的 batch size 对比

本次小 batch 每轮至少采样 1,000 步，大 batch 每轮至少采样 4,000 步，两者都更新策略 100 次。因此，小 batch 使用约 10 万训练步，大 batch 使用约 40 万训练步。

两组曲线终点可以用于描述各自训练结束时的表现，但不能据此直接判断同预算下谁更省样本。研究样本效率时，可以比较共同的 0～10 万步区间。

本次小 batch 的 reward-to-go 加优势归一化在 19,072 个训练环境步首次达到平均评估回报 200。对应大 batch 配置用了 81,146 步。这个结果说明小 batch 在本次运行的“首次达到平均满分”指标上更省样本，不代表它必然更稳定或在所有随机种子下都更好。

### 5.2 HalfCheetah 的 baseline 对比

三种配置每轮均采样 5,000 步，训练 100 轮，总训练预算都是 50 万步。因此，可以在相同训练环境步数处比较策略表现。

不过，使用 baseline 会增加 critic 的训练成本。每轮训练 critic 5 次与 1 次的计算成本也不同。这说明“采样预算相同”不等于“计算预算相同”。

标准 baseline 的三次尝试中，只有第三次在训练结束时超过平均回报 300。该次最后一轮回报为 332.79，但最后 10 轮均值为 278.46。因此，应描述为结束时达标，不能描述为已经稳定保持在 300 以上。

本次原始训练入口固定了 NumPy 和 PyTorch 的种子，但未显式固定 Gym 环境的随机种子。不同尝试之间的差异不能仅归因于种子参数对应的某一个随机来源。

## 6. 不要把训练损失当作最终成绩

Actor loss 和 critic loss 主要用于理解、检查训练过程，不是任务表现的替代指标。

- Actor loss 会受到优势数值尺度和标准化方式影响，通常不适合直接跨配置比较绝对大小。
- Critic loss 较低，只说明在当前数据与目标下预测误差较小，不保证策略回报更高。
- 强化学习中的策略和采样数据不断变化，critic 的预测目标也会变化，因此损失不必单调下降。

最终仍应根据任务回报、成功率和约束指标判断策略是否有效。

## 7. 阅读实验结果的检查清单

1. 这张图想说明任务表现、样本效率，还是其他能力？
2. 横轴是什么，训练与评估成本分别如何统计？
3. 比较位置对应的样本或计算预算是否相同？
4. 展示的是最高分、最终模型表现，还是多个检查点的平均值？
5. 是否区分首次达标与稳定达标？
6. 是否使用多个独立训练种子，并说明误差条的含义？
7. 环境版本、评估方式和调参预算是否可比？
8. 结论是否超出了现有任务、种子和数据能够支持的范围？

评价的重点不是找一个数字宣布某种方法最好，而是说明它在什么条件下，使用多少资源，能够以多高的可靠性达到什么表现。
